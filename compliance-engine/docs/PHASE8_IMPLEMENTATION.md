# Stage 8 Remediation — Phase 8 Implementation

## Scope

Phase 8 replaces the legacy markup-only archive with a deterministic BCF XML
2.1 exporter built on the Phase 7 `ValidationReport` and canonical
`BuildingModel`.

## Runtime flow

```text
ValidationReport + BuildingModel
        ↓
BCF eligibility filter
        ↓
Stable topic/viewpoint IDs
        ↓
markup.bcf + viewpoint.bcfv + optional snapshot.png
        ↓
archive structural/XSD-subset validation
        ↓
compliance_issues.bcf + manifest.json
```

## Export eligibility

A finding is exported when it is actionable and model-addressable:

- stage is schema, quality, or compliance;
- verdict is `FAIL`, `NEEDS_REVIEW`, or `NOT_EVALUATED`;
- it has an IFC `GlobalId`, or during the compatibility period, a stable
  internal element ID.

Global findings without an element anchor remain in JSON/HTML/PDF and are
listed in the BCF manifest as skipped. Empty BCF topics are deliberately not
created.

## IFC component selection

IFC-backed topics use the original 22-character IFC `GlobalId`:

```xml
<Components>
  <Selection>
    <Component IfcGuid="..." />
  </Selection>
  <Visibility DefaultVisibility="true" />
</Components>
```

Internal detector IDs are never written as `IfcGuid`.

## Topic identity

Topic and viewpoint GUIDs are UUID5 values derived from the stable Phase 7
`finding_id`. Re-running the exporter with the same report timestamp and
content produces byte-identical archives.

## Viewpoints and snapshots

- IFC-addressable findings receive `viewpoint.bcfv`.
- A top-down orthographic camera is generated only from trusted canonical
  geometry.
- A PNG snapshot is generated from the same geometry when Pillow is available.
- No camera coordinates are invented when geometry is unavailable.
- Findings without a trustworthy IFC GlobalId are skipped from BCF with an
  explicit manifest reason and remain available in JSON/HTML/PDF.

## Project and archive files

A generated archive may contain:

```text
bcf.version
project.bcfp
<topic-guid>/markup.bcf
<topic-guid>/viewpoint.bcfv
<topic-guid>/snapshot.png
```

`project.bcfp` is emitted when the report has a project identifier.

## Validation

`reporting.bcf_exporter.validate_bcf_archive()` verifies:

- readable ZIP archive;
- BCF version 2.1;
- project file structure;
- topic folder/GUID consistency;
- topic metadata;
- viewpoint reference integrity;
- component selection and IFC GUID format;
- snapshot references;
- generated-output conformance using local XSD subsets derived from the
  official BCF XML 2.1 structures.

The local schemas intentionally validate the constructs generated by this
engine. They are not advertised as a general-purpose validator for arbitrary
third-party BCF files.

## CLI tools

Validate an archive:

```bash
python -m scripts.validate_bcf artifacts/phase8_acceptance/compliance_issues.bcf
```

Run the complete acceptance flow:

```bash
python -m scripts.run_phase8_acceptance \
  --ifc tests/fixtures/sample_plan.ifc \
  --clauses data/mabhas_clauses.json \
  --output-dir artifacts/phase8_acceptance
```

## Dependencies

Phase 8 adds direct runtime dependencies:

- `lxml` for XML generation and schema validation;
- `Pillow` for deterministic PNG snapshots.
